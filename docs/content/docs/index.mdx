**regit** implementiert Git-Operationen direkt in **Java 25** — ohne externe Laufzeitabhängigkeiten, ohne JGit und ohne `git`-Subprozesse. Alle geschriebenen Objekte, Indizes, Refs, Worktrees und Konfliktzustände sind 100 % interoperabel mit nativem Git.

<Callout type="info" title="Objektorientierte API statt String-Konkatenation">
  Anstelle von CLI-Flags arbeitet `regit` mit typsicheren Domain-Objekten wie `Repository`, `Branch`, `RemoteBranch`, `Commit`, `CommitRef`, `Diff`, `Log`, `MergeOptions` und `RebaseOptions`.
</Callout>

## Quickstart in 30 Sekunden

Der folgende Workflow initialisiert ein Repository, erstellt einen ersten Commit, isoliert Änderungen auf einem Feature-Branch in einem eigenen Worktree, prüft den Diff, merged zurück und räumt sauber auf:

```java title="Quickstart.java"
import io.github.regit.*;
import java.nio.file.*;
import java.time.OffsetDateTime;

Path repoDir = Path.of("my-project");
var author = new Identity("Alix", "alix@example.org", OffsetDateTime.now());

// 1. Repository initialisieren und ersten Commit erstellen
Repository mainRepo = Repository.init(repoDir, "main");
Files.writeString(repoDir.resolve("README.md"), "# My Project\n");
mainRepo.stageAll();
Commit initial = mainRepo.commit(mainRepo.commit("feat: initial commit\n", author, author));

// 2. Isolierten Worktree für einen Task oder Agenten anlegen
Path featureDir = Path.of("my-project-docs");
Repository agent = mainRepo.addWorktreeNewBranch(featureDir, "agent/docs", initial);

Files.writeString(featureDir.resolve("README.md"), "# My Project\n\nMit Dokumentation.\n");
agent.stageAll();
Commit docsCommit = agent.commit("docs: update README\n", author, author, CommitOptions.defaults());

// 3. Diff zwischen Branch und Commit prüfen
Diff diff = mainRepo.diff(initial, docsCommit);
System.out.println(diff.formatStat());
System.out.println(diff.formatPatch());

// 4. Zurück in main mergen und Worktree sowie Branch aufräumen
Branch docsBranch = mainRepo.branch("agent/docs");
mainRepo.merge(docsBranch, author, "merge: integrate docs\n", MergeOptions.defaults().noFastForward());
mainRepo.removeWorktree(agent);
mainRepo.deleteBranch(docsBranch);
```

## Das `CommitRef`-Prinzip

Viele Git-Operationen erwarten ein Ziel, das auf einen Commit zeigt. In `regit` implementieren die wichtigsten Typen das gemeinsame `sealed interface CommitRef`:

- `Commit` — unveränderliches Commit-Objekt (z. B. aus `headCommit()`, `commit(...)`, `log(...)`)
- `Branch` — lokaler Branch-Handle, folgt automatisch dem aktuellen Tip
- `RemoteBranch` — Remote-Tracking-Branch (z. B. `origin/main`)
- `CommitRef.of("HEAD~2")` — beliebige Git-Revisionsausdrücke (`v1.0`, `HEAD^2`, gekürzte SHAs)

```java title="CommitRefExample.java"
Branch main = repo.branch("main");
RemoteBranch originMain = repo.remoteBranch("origin", "main");
Commit release = repo.commit("v1.0");

// Alle Kombinationen funktionieren direkt ohne String-Umwandlung
boolean merged = repo.isAncestor(release, main);
Optional<Commit> base = repo.mergeBase(originMain, main);
Diff changes = repo.diff(originMain, main);
String readme = repo.showText(release, Path.of("README.md"));
```
