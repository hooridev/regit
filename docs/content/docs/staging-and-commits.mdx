## Checking Status (`git status`)

`repo.status()` returns a structured `Status` record with staged, unstaged, and untracked paths in Git's canonical byte order. Worktree `.gitignore` files and `.git/info/exclude` are evaluated automatically.

```java title="CheckStatus.java"
Status status = repo.status();

// Staged (Index vs. HEAD)
status.staged().forEach((path, change) ->
    System.out.println("staged   " + change + " " + path));

// Unstaged (Working Tree vs. Index)
status.unstaged().forEach((path, change) ->
    System.out.println("unstaged " + change + " " + path));

// Untracked (new, non-ignored files)
status.untracked().forEach(path ->
    System.out.println("untracked " + path));
```

### Ignored Files & Upstream Tracking (`--ignored` / `-sb`)

```java title="StatusExtras.java"
// List ignored untracked files (`git status --ignored`)
SortedSet<String> ignored = repo.ignoredFiles();

// Upstream tracking & ahead/behind counts (`git status -sb`)
repo.branchTracking().ifPresent(tracking -> {
    System.out.printf("## %s...%s %s%n",
        repo.abbrevRef(),
        tracking.upstream().fullName(),
        tracking.formatShort()); // e.g. "[ahead 2, behind 1]"
});
```

## Staging Files (`git add`)

`regit` covers all common staging workflows with explicit, readable methods:

<Tabs items={['All (-A)', 'Tracked Only (-u)', 'Specific Paths / Dirs', 'Intent-to-Add (-N)']}>
  <Tab value="All (-A)">
```java title="StageAll.java"
// Stage all modified, deleted, and non-ignored untracked files
repo.stageAll();

// Scoped to specific directories or files
repo.stageAll(Path.of("src"), Path.of("README.md"));
```
  </Tab>
  <Tab value="Tracked Only (-u)">
```java title="StageUpdated.java"
// Stage all modified and deleted tracked files without adding untracked files
repo.stageUpdated();

// Scoped to src/
repo.stageUpdated(Path.of("src"));
```
  </Tab>
  <Tab value="Specific Paths / Dirs">
```java title="StagePaths.java"
// Exact repo-relative file paths; missing tracked files stage a deletion
repo.stage("README.md", "src/App.java");

// Path overload supports both individual files and recursive directories
repo.stage(Path.of("src/main"), Path.of("pom.xml"));
```
  </Tab>
  <Tab value="Intent-to-Add (-N)">
```java title="StageIntentToAdd.java"
// Record untracked files in index v3 as intent-to-add (visible in diff(), omitted from diffStaged())
repo.stageIntentToAdd("src/NewFeature.java");
repo.stageIntentToAdd(Path.of("docs/notes.md"));
```
  </Tab>
</Tabs>

<Callout type="warn" title="Atomic ignore protection on explicit staging">
  If any new path passed to `stage(...)` or `stageIntentToAdd(...)` is excluded by `.gitignore`, the call fails atomically with an `IOException` before writing any blobs or modifying the index.
</Callout>

## Creating Commits (`git commit`)

Pass a single `Identity` to use the same person as both author and committer — or pass `(author, committer)` explicitly when they differ (e.g. a CI bot committing on behalf of a developer).

```java title="BasicCommit.java"
import io.github.regit.*;
import java.time.OffsetDateTime;

var author = new Identity("Alix", "alix@example.org", OffsetDateTime.now());

repo.stageAll();
Commit created = repo.commit(
    "feat(api): add search endpoint\n\nIncludes pagination and filtering.\n",
    author
);

System.out.println("Created commit: " + created.shortId());
```

### Common Commit Workflows (`-a`, `--amend`, `--no-edit`, `--fixup`)

```java title="CommitVariants.java"
var author = new Identity("Alix", "alix@example.org", OffsetDateTime.now());
var committer = new Identity("CI Bot", "ci@example.org", OffsetDateTime.now());

// 1. Auto-stage modified/deleted tracked files and commit (`git commit -a -m ...`)
Commit c1 = repo.commitAll("fix: handle null input\n", author);

// 2. Replace HEAD commit with a new message (explicit separate committer) (`git commit --amend -m ...`)
Commit c2 = repo.amend("fix(parser): handle null input safely\n", author, committer);

// 3. Amend HEAD while keeping its original author and message (`git commit --amend --no-edit`)
repo.stage("src/ParserTest.java");
Commit c3 = repo.amendNoEdit(committer);

// 4. Create a fixup! commit for later `rebase --autosquash` (`git commit --fixup=<commit>`)
Commit target = repo.commit("HEAD~2");
Commit fixup = repo.fixup(target, author);
// Produces exact message: "fixup! <subject of target>\n"

// 5. Combine fixup with -a (`git commit -a --fixup=<commit>`)
Commit fixupAll = repo.fixup(target, author, CommitOptions.defaults().all());

// 6. Explicitly allow an empty commit (`git commit --allow-empty`)
Commit trigger = repo.commit("chore: trigger build\n", author,
    CommitOptions.defaults().allowEmpty());
```

<Callout type="info" title="Detached HEAD & concluding merges">
  `commit(...)` works both on local branches and on a **detached HEAD**. When a merge is paused (`MERGE_HEAD` exists) and all conflicts are staged, `commit(...)` automatically writes a 2-parent merge commit and cleans up merge state.
</Callout>
