## Status prüfen (`git status`)

`repo.status()` liefert ein strukturiertes `Status`-Objekt mit allen gestagten, ungestagten und ungetrackten Pfaden in kanonischer Git-Byte-Reihenfolge. `.gitignore` und `.git/info/exclude` werden automatisch berücksichtigt.

```java title="CheckStatus.java"
Status status = repo.status();

// Staged (Index vs. HEAD)
status.staged().forEach((path, change) ->
    System.out.println("staged   " + change + " " + path));

// Unstaged (Worktree vs. Index)
status.unstaged().forEach((path, change) ->
    System.out.println("unstaged " + change + " " + path));

// Untracked (neue, nicht ignorierte Dateien)
status.untracked().forEach(path ->
    System.out.println("untracked " + path));
```

### Ignorierte Dateien & Upstream-Status (`--ignored` / `-sb`)

```java title="StatusExtras.java"
// Alle ignorierten Dateien auflisten (analog `git status --ignored`)
SortedSet<String> ignored = repo.ignoredFiles();

// Upstream-Tracking & Ahead/Behind (analog `git status -sb`)
repo.branchTracking().ifPresent(tracking -> {
    System.out.printf("## %s...%s %s%n",
        repo.abbrevRef(),
        tracking.upstream().fullName(),
        tracking.formatShort()); // z. B. "[ahead 2, behind 1]"
});
```

## Dateien stagen (`git add`)

`regit` deckt alle gängigen Staging-Varianten direkt über sprechende Methoden ab:

<Tabs items={['Alles (-A)', 'Nur getrackte (-u)', 'Gezielte Pfade / Ordner', 'Intent-to-Add (-N)']}>
  <Tab value="Alles (-A)">
```java title="StageAll.java"
// Alle geänderten, gelöschten und neuen (nicht ignorierten) Dateien stagen
repo.stageAll();

// Eingeschränkt auf bestimmte Verzeichnisse oder Dateien
repo.stageAll(Path.of("src"), Path.of("README.md"));
```
  </Tab>
  <Tab value="Nur getrackte (-u)">
```java title="StageUpdated.java"
// Alle geänderten und gelöschten bereits getrackten Dateien stagen (keine Untracked)
repo.stageUpdated();

// Nur innerhalb von src/
repo.stageUpdated(Path.of("src"));
```
  </Tab>
  <Tab value="Gezielte Pfade / Ordner">
```java title="StagePaths.java"
// Einzelne Dateien (repo-relativ); fehlende getrackte Dateien stagen eine Löschung
repo.stage("README.md", "src/App.java");

// Path-Überladung unterstützt sowohl einzelne Dateien als auch ganze Ordner
repo.stage(Path.of("src/main"), Path.of("pom.xml"));
```
  </Tab>
  <Tab value="Intent-to-Add (-N)">
```java title="StageIntentToAdd.java"
// Neue Datei im Index v3 als intent-to-add vormerken (erscheint in diff(), nicht in diffStaged())
repo.stageIntentToAdd("src/NewFeature.java");
repo.stageIntentToAdd(Path.of("docs/notes.md"));
```
  </Tab>
</Tabs>

<Callout type="warn" title="Ignore-Schutz bei explizitem Staging">
  Wenn beim expliziten Aufruf von `stage(...)` oder `stageIntentToAdd(...)` ein noch ungetrackter Pfad durch `.gitignore` ausgeschlossen ist, bricht die Operation atomar mit `IOException` ab, ohne Blobs oder den Index zu verändern.
</Callout>

## Commits erstellen (`git commit`)

Jeder Commit trägt explizite `Identity`-Objekte für Author und Committer mit Zeitstempel und UTC-Offset — ideal für reproduzierbare Builds und Agenten-Commits.

```java title="BasicCommit.java"
import io.github.regit.*;
import java.time.OffsetDateTime;

var author = new Identity("Alix", "alix@example.org", OffsetDateTime.now());

repo.stageAll();
Commit created = repo.commit(
    "feat(api): add search endpoint\n\nIncludes pagination and filtering.\n",
    author,
    author,
    CommitOptions.defaults()
);

System.out.println("Created commit: " + created.shortId());
```

### Alle gängigen Commit-Varianten (`-a`, `--amend`, `--no-edit`, `--fixup`)

```java title="CommitVariants.java"
var author = new Identity("Alix", "alix@example.org", OffsetDateTime.now());
var committer = new Identity("CI Bot", "ci@example.org", OffsetDateTime.now());

// 1. Tracked Changes automatisch stagen & committen (`git commit -a -m ...`)
Commit c1 = repo.commitAll("fix: handle null input\n", author, author);

// 2. Letzten Commit mit neuer Nachricht überschreiben (`git commit --amend -m ...`)
Commit c2 = repo.amend("fix(parser): handle null input safely\n", author, committer);

// 3. Letzten Commit ändern, Author & Message behalten (`git commit --amend --no-edit`)
repo.stage("src/ParserTest.java");
Commit c3 = repo.amendNoEdit(committer);

// 4. Fixup-Commit für späteres `rebase --autosquash` (`git commit --fixup=<commit>`)
Commit target = repo.commit("HEAD~2");
Commit fixup = repo.fixup(target, author, author);
// Erzeugt exakt: "fixup! <subject von target>\n"

// 5. Fixup kombiniert mit -a (`git commit -a --fixup=<commit>`)
Commit fixupAll = repo.fixup(target, author, author, CommitOptions.defaults().all());

// 6. Leeren Commit explizit erlauben (`git commit --allow-empty`)
Commit trigger = repo.commit("chore: trigger build\n", author, author,
    CommitOptions.defaults().allowEmpty());
```

<Callout type="info" title="Detached HEAD & Merge-Abschluss">
  `commit(...)` funktioniert sowohl auf lokalen Branches als auch im **Detached-HEAD-Modus**. Ist ein Merge pausiert (`MERGE_HEAD` vorhanden), erzeugt `commit(...)` nach aufgelösten Konflikten automatisch einen 2-Parent-Merge-Commit.
</Callout>
