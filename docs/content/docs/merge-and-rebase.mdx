## Merge-Strategien (`git merge`)

`merge(...)` akzeptiert jede `CommitRef` (`Branch`, `RemoteBranch`, `Commit`, `CommitRef.of(...)`) und steuert das Verhalten über `MergeOptions`:

```java title="MergeModes.java"
Branch feature = repo.branch("feat/search");
var committer = new Identity("Alix", "alix@example.org", OffsetDateTime.now());

// 1. Standard: Fast-Forward wenn möglich, sonst 2-Parent-Merge-Commit
MergeResult standard = repo.merge(feature, committer, "merge: feat/search\n",
    MergeOptions.defaults());

// 2. Immer einen Merge-Commit erzeugen (`git merge --no-ff`)
MergeResult noFf = repo.merge(feature, committer, "merge: feat/search\n",
    MergeOptions.defaults().noFastForward());

// 3. Nur Fast-Forward erlauben, sonst IOException (`git merge --ff-only`)
MergeResult ffOnly = repo.merge(repo.remoteBranch("origin", "main"), committer, "",
    MergeOptions.defaults().fastForwardOnly());

// 4. Merge nur stagen + MERGE_HEAD schreiben, ohne Commit (`git merge --no-commit`)
MergeResult staged = repo.merge(feature, committer, "merge: feat/search\n",
    MergeOptions.defaults().noCommit());
// Danach prüfen/anpassen und abschließen (erzeugt automatisch 2-Parent-Commit):
Commit mergeCommit = repo.commit(null, committer, committer, CommitOptions.defaults());
```

## Konflikte mit `--ours` / `--theirs` auflösen

Standardmäßig bricht `merge` bzw. `rebase` bei Konflikten atomar mit `MergeConflict` ab, ohne den Worktree zu verändern. Mit `.allowConflicts()` schreibt `regit` stattdessen den vollständigen Git-Konfliktzustand (Konfliktmarker `<<<<<<<`/`=======`/`>>>>>>>`, Index-Stages 1/2/3 sowie `MERGE_HEAD` bzw. `.git/rebase-merge/`):

```java title="ResolveMergeConflict.java"
MergeResult result = repo.merge(
    repo.branch("feat/conflict"),
    committer,
    "merge: resolve conflict\n",
    MergeOptions.defaults().allowConflicts()
);

if (result.isConflicted()) {
    System.out.println("Konflikte: " + repo.conflictedFiles());

    // Datei 1: unsere Version übernehmen (`git checkout --ours`)
    repo.checkoutOurs("config/app.properties");

    // Datei 2: eingehende Version übernehmen (`git checkout --theirs`)
    repo.checkoutTheirs(Path.of("docs/README.md"));

    // Alternativ: Datei manuell bearbeiten und danach stagen
    repo.stage("config/app.properties", "docs/README.md");

    // Merge mit 2 Parents abschließen
    Commit merged = repo.commit("merge: resolved conflicts\n", committer, committer,
        CommitOptions.defaults());
}
```

### Merge abbrechen (`git merge --abort`)

```java title="AbortMerge.java"
if (repo.isMergeInProgress()) {
    repo.abortMerge(); // Stellt HEAD, Index und Working Tree sauber wieder her
}
```

## Rebase (`git rebase`)

### Rebase auf einen Branch oder `RemoteBranch` (`origin/main`)

```java title="RebaseOntoOrigin.java"
repo.fetch("origin");
RemoteBranch originMain = repo.remoteBranch("origin", "main");

RebaseResult res = repo.rebase(originMain, committer, RebaseOptions.defaults());
System.out.println("Rebase status: " + res.status() + " -> " + res.head().orElseThrow().shortId());
```

### Teil-Historie umhängen (`git rebase --onto`)

```java title="RebaseOnto.java"
// Nur die Commits in `oldParent..HEAD` auf `newBase` umhängen
Branch oldParent = repo.branch("feat/base");
Branch newBase = repo.branch("main");

RebaseResult res = repo.rebase(
    oldParent,
    committer,
    RebaseOptions.defaults().onto(newBase)
);
```

### Autosquash (`git rebase -i --autosquash`) & eigene Pläne

`fixup!`-Commits (erstellt mit `repo.fixup(...)`) und `squash!`-Commits werden automatisch hinter ihren Ziel-Commit einsortiert und eingearbeitet:

<Tabs items={['Autosquash', 'Expliziter Rebase-Plan']}>
  <Tab value="Autosquash">
```java title="RebaseAutosquash.java"
RemoteBranch originMain = repo.remoteBranch("origin", "main");

// Sortiert alle `fixup!` und `squash!` Commits automatisch ein
RebaseResult res = repo.rebase(
    originMain,
    committer,
    RebaseOptions.defaults().autosquash()
);
```
  </Tab>
  <Tab value="Expliziter Rebase-Plan">
```java title="InteractiveRebasePlan.java"
Branch main = repo.branch("main");
List<Commit> commits = repo.log(Log.range(main, repo.currentBranch()).reverse());

List<RebaseStep> plan = List.of(
    RebaseStep.reword(commits.get(0), "feat: polished title\n"),
    RebaseStep.fixup(commits.get(1)),   // in commits[0] einfalten
    RebaseStep.drop(commits.get(2)),    // überspringen
    RebaseStep.pick(commits.get(3))
);

RebaseResult res = repo.rebase(main, committer, RebaseOptions.defaults().plan(plan));
```
  </Tab>

### Pausierbarer Rebase (`--continue` & `--abort`)

```java title="RebaseConflictFlow.java"
RebaseResult res = repo.rebase(
    repo.remoteBranch("origin", "main"),
    committer,
    RebaseOptions.defaults().allowConflicts()
);

while (res.isConflicted()) {
    System.out.println("Stopp bei Commit: " + res.stoppedCommit().orElseThrow().shortId());
    System.out.println("Konflikte: " + res.conflicts());

    // Konflikte lösen (z. B. eingehenden Commit behalten) und stagen
    for (String path : res.conflicts()) {
        repo.checkoutTheirs(path);
        repo.stage(path);
    }

    // Rebase fortsetzen (`git rebase --continue`)
    res = repo.continueRebase(committer);
}

// Oder jederzeit abbrechen (`git rebase --abort`):
// if (repo.isRebaseInProgress()) repo.abortRebase();
```

<Callout type="info" title="100 % Interoperabilität mit nativem Git">
  Ein von `regit` pausierter Merge oder Rebase schreibt exakt `.git/MERGE_HEAD` bzw. `.git/rebase-merge/*` und Index-Stages 1–3. Du kannst den Zustand jederzeit auch mit nativem `git status`, `git rebase --continue` oder `git merge --abort` weiterbearbeiten — und umgekehrt.
</Callout>
