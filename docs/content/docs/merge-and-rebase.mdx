## Merge Modes (`git merge`)

`merge(...)` accepts any `CommitRef` (`Branch`, `RemoteBranch`, `Commit`, `CommitRef.of(...)`) and configures behavior via `MergeOptions`:

```java title="MergeModes.java"
Branch feature = repo.branch("feat/search");
var committer = new Identity("Alix", "alix@example.org", OffsetDateTime.now());

// 1. Default: fast-forward if possible, otherwise write a 2-parent merge commit
MergeResult standard = repo.merge(feature, committer, "merge: feat/search\n",
    MergeOptions.defaults());

// 2. Always write a merge commit (`git merge --no-ff`)
MergeResult noFf = repo.merge(feature, committer, "merge: feat/search\n",
    MergeOptions.defaults().noFastForward());

// 3. Fast-forward only; throw IOException on divergence (`git merge --ff-only`)
MergeResult ffOnly = repo.merge(repo.remoteBranch("origin", "main"), committer, "",
    MergeOptions.defaults().fastForwardOnly());

// 4. Stage merge & write MERGE_HEAD without committing (`git merge --no-commit`)
MergeResult staged = repo.merge(feature, committer, "merge: feat/search\n",
    MergeOptions.defaults().noCommit());
// Inspect or edit staged files, then conclude (writes 2-parent merge commit):
Commit mergeCommit = repo.commit(null, committer, CommitOptions.defaults());
```

## Resolving Conflicts with `--ours` / `--theirs`

By default, `merge` and `rebase` throw `MergeConflict` atomically without modifying the working tree or index. Opt in to `.allowConflicts()` to write full Git conflict state (conflict markers `<<<<<<<`/`=======`/`>>>>>>>`, index stages 1/2/3, and `MERGE_HEAD` or `.git/rebase-merge/`):

```java title="ResolveMergeConflict.java"
MergeResult result = repo.merge(
    repo.branch("feat/conflict"),
    committer,
    "merge: resolve conflict\n",
    MergeOptions.defaults().allowConflicts()
);

if (result.isConflicted()) {
    System.out.println("Conflicted paths: " + repo.conflictedFiles());

    // File 1: keep our version (`git checkout --ours`)
    repo.checkoutOurs("config/app.properties");

    // File 2: take incoming version (`git checkout --theirs`)
    repo.checkoutTheirs(Path.of("docs/README.md"));

    // Or edit files manually, then stage to clear conflict stages 1..3
    repo.stage("config/app.properties", "docs/README.md");

    // Conclude the 2-parent merge commit
    Commit merged = repo.commit("merge: resolved conflicts\n", committer);
}
```

### Aborting a Merge (`git merge --abort`)

```java title="AbortMerge.java"
if (repo.isMergeInProgress()) {
    repo.abortMerge(); // Restores HEAD, index, and working tree cleanly
}
```

## Rebase (`git rebase`)

### Rebasing onto a Branch or `RemoteBranch` (`origin/main`)

```java title="RebaseOntoOrigin.java"
repo.fetch("origin");
RemoteBranch originMain = repo.remoteBranch("origin", "main");

RebaseResult res = repo.rebase(originMain, committer, RebaseOptions.defaults());
System.out.println("Rebase status: " + res.status() + " -> " + res.head().orElseThrow().shortId());
```

### Transplanting a Commit Range (`git rebase --onto`)

```java title="RebaseOnto.java"
// Replay only `oldParent..HEAD` onto `newBase`
Branch oldParent = repo.branch("feat/base");
Branch newBase = repo.branch("main");

RebaseResult res = repo.rebase(
    oldParent,
    committer,
    RebaseOptions.defaults().onto(newBase)
);
```

### Autosquash (`git rebase -i --autosquash`) & Custom Plans

`fixup!` commits (created with `repo.fixup(...)`) and `squash!` commits are automatically reordered directly after their target commit and folded in:

<Tabs items={['Autosquash', 'Explicit Rebase Plan']}>
  <Tab value="Autosquash">
```java title="RebaseAutosquash.java"
RemoteBranch originMain = repo.remoteBranch("origin", "main");

// Automatically reorders and applies all `fixup!` and `squash!` commits
RebaseResult res = repo.rebase(
    originMain,
    committer,
    RebaseOptions.defaults().autosquash()
);
```
  </Tab>
  <Tab value="Explicit Rebase Plan">
```java title="InteractiveRebasePlan.java"
Branch main = repo.branch("main");
List<Commit> commits = repo.log(Log.range(main, repo.currentBranch()).reverse());

List<RebaseStep> plan = List.of(
    RebaseStep.reword(commits.get(0), "feat: polished title\n"),
    RebaseStep.fixup(commits.get(1)),   // fold into commits[0]
    RebaseStep.drop(commits.get(2)),    // drop commit
    RebaseStep.pick(commits.get(3))
);

RebaseResult res = repo.rebase(main, committer, RebaseOptions.defaults().plan(plan));
```
  </Tab>
</Tabs>

### Pausable Rebase (`--continue` & `--abort`)

```java title="RebaseConflictFlow.java"
RebaseResult res = repo.rebase(
    repo.remoteBranch("origin", "main"),
    committer,
    RebaseOptions.defaults().allowConflicts()
);

while (res.isConflicted()) {
    System.out.println("Stopped at commit: " + res.stoppedCommit().orElseThrow().shortId());
    System.out.println("Conflicts: " + res.conflicts());

    // Resolve conflicts (e.g. keep incoming commit's changes) and stage
    for (String path : res.conflicts()) {
        repo.checkoutTheirs(path);
        repo.stage(path);
    }

    // Resume rebase (`git rebase --continue`)
    res = repo.continueRebase(committer);
}

// Or abort at any time (`git rebase --abort`):
// if (repo.isRebaseInProgress()) repo.abortRebase();
```

<Callout type="info" title="100% Native Git Interoperability">
  A paused merge or rebase writes standard `.git/MERGE_HEAD` or `.git/rebase-merge/*` files along with index stages 1–3. You can inspect, continue, or abort a `regit`-initiated conflict with native `git` — and vice versa.
</Callout>
